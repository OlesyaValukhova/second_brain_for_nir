# Системный анализ и согласованный комплект UML

Дата: 26.10.2026. Статус: предлагаемая модель предметной области и аналитической процедуры. Подготовлено для доработки НИР‑1/НИР‑2 по [[RQ-001]]. Диаграммы не описывают подтверждённый регламент конкретного учреждения и не являются отчётом наблюдения за семьями.

## 1. Граница объекта и задача системного анализа

Объект целесообразно уточнить как **территориальную систему предложения и размещения организованных внешкольных занятий для детей**. Пространственная доступность — оцениваемое свойство этой системы, а не сама система. Предмет исследования — способ пространственной оценки возрастно допустимого предложения с учётом размещения площадок и заданных условий пути. Это уточнение для обсуждения, а не незаметная замена канонической постановки.

В систему входят поставщики, программы, их группы, направления, условия участия и реальные места проведения. Пешеходная сеть и жилые точки задают среду пространственного взаимодействия. Семья может использовать опубликованное предложение при выборе, но исследование не восстанавливает её предпочтения и фактические поездки. Наблюдаемая база содержит публичные записи и их качество, а не полную деятельность системы.

Необходимо различать три вопроса: **что существует** — концептуальная модель U2; **какая предметная деятельность использует сведения** — U4; **как исследователь получает оценку** — U1, U3 и U5. Ранее схема из последовательности «сбор — расчёт — вывод» раскрывала только третий вопрос и не заменяла предметный процесс из требований презентации.

Качество системы в пределах измеряемого компонента характеризуется числом достижимых возрастно подходящих площадок, наличием близкого варианта направления и разнообразием достижимых направлений. Качество сведений характеризуется полнотой возраста, периода, мест, согласованностью карточек и групп, точностью географической привязки и проверяемостью происхождения. Эти два уровня не смешиваются: высокая полнота каталога не означает высокую доступность, а неизвестное место не означает отсутствие занятия.

## 3. Сущности, роли и кратности U2

Организация выступает поставщиком программ. В исследовательской модели одна программа имеет одного идентифицированного поставщика и ноль или больше известных групп. Нулевое число групп означает отсутствие подтверждённых записей в текущем наборе, а не доказательство прекращения деятельности. Совместные программы могут потребовать расширения модели поставщиков; текущий каталог и базовый алгоритм этого не устанавливают.

Группа реализует одну программу; её собственный возраст и период могут отличаться от обобщённой карточки. Поэтому «возрастное утверждение» выделено отдельно. Оно связано с одной программой и необязательно уточняющей группой. Инвариант требует: если группа указана, она относится к той же программе. Для каждого утверждения сохраняются источники; несогласованность нескольких утверждений не разрешается уничтожением одного из них.

Размещение моделируется через класс «Привязка занятия к месту». Он связывает одну программу, необязательно конкретную группу и одну площадку; содержит статус и основания. Такое представление допускает несколько мест одной программы и совместное использование площадки разными организациями. Никакая композиция не утверждается для связи «организация — площадка»: удаление организации из исследовательского набора не должно автоматически уничтожать физическое место или другие связанные программы.

Кратности отражают известность в модели, а не обещание полноты реального мира. Например, программа с нулём привязок имеет неизвестное место; это не программа «без места» как утверждённое свойство действительности. Ноль направлений означает неопределённость классификации. Такая программа не создаёт дополнительное известное направление, но при подтверждённых возрасте и площадке может входить в общее число площадок.

| Ассоциация | Роли концов | Кратности |
|---|---|---|
| Организация — программа | поставщик / предложения | 1 / 0..* |
| Программа — группа | программа / реализации | 1 / 0..* |
| Программа — возрастное утверждение | предмет утверждения / возрастные сведения | 1 / 0..* |
| Группа — возрастное утверждение | уточняющая группа / сведения группы | 0..1 / 0..* |
| Программа — направление | программы / категории | 0..* / 0..* |
| Программа — привязка места | программа / размещения | 1 / 0..* |
| Группа — привязка места | уточняющая группа / размещения группы | 0..1 / 0..* |
| Площадка — привязка места | место / связанные занятия | 1 / 0..* |
| Свидетельство — утверждение либо привязка | основания / документируемые записи | 1..* / 0..* |

Роли вынесены также в таблицу, чтобы не перегружать подписи у узлов с несколькими ассоциациями. На рисунке кратности привязаны к концам ассоциаций; обычная линия не означает поток данных или последовательность действий.

## 4. Аналитическая модель U3 и проверяемые ограничения

U3 отделяет предметные сущности от вычислительных. Срез данных задаёт происхождение предложения; сценарий фиксирует дату анализа, правило актуальности, возрастного допуска, разрешения неизвестного, скорость и бюджеты. Один сценарий применяется к одному набору версий входов, а изменения получают новый идентификатор. Возрастной набор содержит состояния 1/0/? и признаки r(s,a), q(s,k,a), а не только удалённые неподходящие строки.

Исходная точка принадлежит одной территории агрегации в заданном разбиении. Если территории перекрываются, используется другой явно названный набор агрегации. Затрата пути относится к конкретным началу, назначению, сети и условиям сценария. Разделяются рассчитанный путь, недостижимость, невозможность привязки и ещё не выполненный расчёт. Эти состояния нельзя заменить нулевым временем.

Результат точки имеет ключ «сценарий — исходная точка — возраст — бюджет». Число N строится по r(s,a), то есть наличию подходящей программы независимо от известности профиля. Направления H и ближайший вариант D используют q(s,k,a). Матрица пути переиспользуется между возрастами только при одинаковой сети и транспортных условиях. Смена возраста при фиксированном пути не должна скрыто менять точки отправления.

Инварианты согласования с алгоритмом:

1. Для одной пары точка/площадка и фиксированных условий маршрут не зависит от возраста.
2. Несколько подходящих программ одного места увеличивают число программ, но не N площадок.
3. Неизвестный профиль не исключает известную подходящую площадку из N, но не увеличивает H.
4. Объединение возрастных интервалов групп не заполняет разрывы между ними.
5. Неизвестная актуальность не превращается в подтверждённую по умолчанию.
6. N⁻/N⁺ ограничивают позиционированную часть при заданных разрешениях неизвестных значений, а не всё реальное предложение города.
7. Отсутствие назначения в обследованном охвате не доказывает его отсутствия во всём городе; ближайшая оценка может быть цензурирована охватом.

## 5. Предметный процесс U4: что подтверждено и что реконструировано

Публичный каталог действительно предоставляет программы, их карточки, возрастные и адресные сведения; это подтверждено сохранёнными ответами Навигатора от 20.10.2026. Из этого не следует подтверждённая последовательность действий семей. Поэтому U4 имеет подпись **«аналитическая реконструкция пользовательского фрагмента, не подтверждённый полный as-is регламент»**. Она задаёт место предполагаемой проблемы: необходимость сопоставить неоднородные сведения о возрасте и месте с возможностью добраться.

В модели семья формулирует условия поиска, получает опубликованные сведения, рассматривает кандидата, при необходимости уточняет условия у поставщика и решает, продолжать ли поиск либо переходить к предусмотренной организацией процедуре обращения. Дорожки обозначают ответственность за действия. Решения снабжены взаимоисключающими условиями; возврат в поиск показан циклом; переход к обращению и завершение без выбора — разные окончания. Каталог не принимает решение за семью, а организация не превращается в исследовательский расчётный модуль.

Зачисление специально вынесено за границу модели. Отсутствуют выдуманные этапы обязательного отбора, автоматического подтверждения или фиксированных сроков, поскольку соответствующий регламент конкретной программы не установлен. Также не моделируются фактические поездки и часы сопровождения. Для утверждения полноценной as-is модели нужны регламент выбранного поставщика, интерфейсные инструкции и/или интервью с участниками. До этого диаграмма полезна как явная гипотеза системного описания, а не как эмпирический результат.

Такое ограничение необходимо сохранить в основном тексте. Без него системный анализ стал бы утверждать неизвестный социальный процесс, хотя исследование располагает каталогом предложений. Если отдельная программа реализуется исключительно дистанционно, её включение в пространственный набор требует отдельного правила; модель очного места не должна применяться автоматически.

## 6. Расчётный процесс U5 и варианты использования U1

U1 задаёт роли исследователя, эксперта данных, предполагаемого пользователя планирования и внешнего источника. Граница охватывает аналитическую процедуру, а не деятельность всех организаций дополнительного образования. Обязательные части представлены include; разбор спорной записи расширяет проверку качества при соответствующем условии. Он не обязан выполняться для каждой записи. Процедура не включает зачисление, самостоятельность ребёнка и доказательство безопасности.

U5 показывает три независимых основания не выпускать карту: критическая ошибка схемы/сбора, неразрешённая ошибка сети или привязки, непрохождение вычислительных проверок. В каждом случае сохраняется диагностика; остановка текущего запуска не означает потерю сохранённых исходников. Неполные записи проходят экспертную проверку, после которой неизвестное может остаться неизвестным. Сценарии разрешения неопределённости формируются явно, а не корректировкой «неудобных» строк.

После вычислений исследователь проверяет маршруты и интерпретацию. Если имеющиеся данные не поддерживают широкий вывод, предусмотрены сужение утверждения/территории либо отложенный выпуск после исправления входов. Диаграмма не требует подтверждения содержательной гипотезы: отсутствие различий является допустимым результатом. Критерии выпуска относятся к правомерности вывода, а не к его эффектности.

Последовательность расчёта в U5 является предлагаемой методикой, а не утверждением о существующем муниципальном процессе. Поэтому U4 и U5 нельзя объединять в одну цепочку: они отвечают на разные требования презентации и имеют разных участников.

## 8. Источники нотации и воспроизведение

Нормативная спецификация — [OMG UML 2.5.1, formal/17-12-05](https://www.omg.org/spec/UML/2.5.1/About-UML), [PDF](https://www.omg.org/spec/UML/2.5.1/PDF). Проверена официальная страница спецификации; огромный нормативный PDF инструментом не извлечён полностью. Практический синтаксис сверялся с официальной документацией PlantUML: [классы](https://plantuml.com/class-diagram), [activity](https://plantuml.com/activity-diagram-beta), [use cases](https://plantuml.com/use-case-diagram). Наличие этих источников подтверждает происхождение нотации, а не содержание нашей предметной модели.

Рендер: Java 21, PlantUML 1.2026.9, Graphviz 2.44.1 из локально доступного комплекта. JAR получен по ссылке официального релиза; URL и SHA‑256 сохранены в `.tools/plantuml/download.json`. Диаграммы не передавались онлайн-сервису. Версия в локальном JAR фиксирована и не заменяется автоматически «последней».

```powershell
java '-Djava.awt.headless=true' -jar .tools/plantuml/plantuml-1.2026.9.jar -charset UTF-8 -tsvg results/nir-1-2-revision-20261026/uml/*.puml
java '-Djava.awt.headless=true' -jar .tools/plantuml/plantuml-1.2026.9.jar -charset UTF-8 -tpng results/nir-1-2-revision-20261026/uml/*.puml
```

Команды выполняются из корня `nir-digital-urbanism`. При отсутствии Java используется установленный локальный путь. Если пакет рендера недоступен, `.puml` и `.svg` остаются проверяемыми редактируемыми источниками.
